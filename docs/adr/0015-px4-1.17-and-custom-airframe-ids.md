# ADR 0015: Upgrade PX4 SITL to 1.17 and use reserved custom airframe IDs

- Status: Accepted
- Date: 2026-07-17
- Related: ADR 0008-0012 (airframe selection, geometry, and generation)

## Context

The project pinned PX4 SITL 1.14.3 and assigned generated model airframes IDs
`4019` and `6001` because those IDs did not collide with that release's posix
airframe set. PX4 1.17.0 adds stock `4019_gz_x500_gimbal`, so the generated
`4019_none_x500_v2` no longer has a unique `SYS_AUTOSTART` ID. PX4 reserves
`22000-22999` for custom model airframes.

## Decision

- Pin PX4 `v1.17.0` to commit
  `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`.
- Bind `none_x500_v2` to `22000` and `none_hexa_x` to `22001`.
- Require every repo-generated airframe ID to be in `22000-22999` and fail
  generation on an out-of-range, duplicate, or colliding ID.
- Do not remove upstream airframes and do not provide aliases for `4019` or
  `6001`. Normal startup clears SITL EEPROM, so stale numeric selections do not
  need a compatibility path.
- Preserve the external MAVLink simulator path, per-instance TCP and GCS port
  conventions, MAVLink 2 behavior, control allocation, and airframe model names.

This supersedes only the numeric `4019` and `6001` bindings in ADR 0008-0012.
Their airframe selection, rotor geometry, and single-source generation decisions
remain in force.

## Consequences

- The resolved `VehicleConfig.px4_sys_autostart` values change without changing
  the YAML schema or Python API.
- PX4 stock and project airframes coexist without pruning or filename-order
  dependence.
- The PX4 image must be rebuilt; manifest freshness checks reject an old image.
- Takeoff, navigation, negative-instability, multi-drone, and flight-performance
  gates must pass without relaxing their thresholds.
